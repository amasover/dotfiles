--- bootstrap --probe-provider: substitution printed, self-resolution silent ---

The stub pacman answers like the real one: a provider name for flashfocus,
the same name back for selfsame, and "target not found" + exit 1 for
anything AUR-only. The AUR-only name goes FIRST: the 2026-07-15 VM run died
on exactly that (set -e/pipefail killed bootstrap on pacman's nonzero exit
before any later name was probed).

$ stub=$(mktemp -d) && printf '#!/bin/sh\nfor a; do :; done\ncase "$a" in\n  flashfocus) echo flashfocus-git ;;\n  selfsame) echo selfsame ;;\n  *) echo "error: target not found: $a" >&2; exit 1 ;;\nesac\n' > "$stub/pacman" && chmod +x "$stub/pacman" && PATH="$stub:$PATH" .local/bin/setup/bootstrap --probe-provider aur-only-pkg flashfocus selfsame > "$stub/out"; echo "rc=$?"
rc=0
$ tr '\t' ' ' < "$stub/out"
flashfocus flashfocus-git
$

--- bootstrap --step-outcome: the 2.38 hold classifier (update's note on stdin) ---

"No version passes the window" is the tolerable wait answer — deferred, not
fatal — and splits on whether an aged version is already installed. Build
failures and unrecognized notes (identity holds) stay fatal in the callers.

$ printf 'aur-quarantine: p has no version older than 14d that is newer than none — nothing to step to yet.\n' | .local/bin/setup/bootstrap --step-outcome 0

$ printf 'aur-quarantine: p has no version older than 14d that is newer than 1.0-1 — nothing to step to yet.\n' | .local/bin/setup/bootstrap --step-outcome 1

--- broken: a multi-line or non-hex --at is refused (rc 1) ---

Seen live: `git ls-remote ... HEAD` matched two refs, and the two-line result
became a broken_at with an embedded newline — malformed TOML. The commit id
must be one line of 4-40 hex chars, however it was obtained.

$ .local/bin/tools/aur-quarantine broken twoline --reason "x" --at "7f050b6e
7f050b6e" 2>&1; echo "rc=$?"
aur-quarantine: '7f050b6e
7f050b6e' is not a commit id (4-40 hex chars, one line).
rc=1

--- metapac-filtered-config: drops named declarations, re-points machine-local (2.38) ---

The staged copy is what `metapac --config-dir` syncs against: named packages
must vanish from every group INCLUDING the absolute-path machine-local group,
dots in names must not act as regex wildcards, and a name declared nowhere is
a note, not an error. metapac-declared over the staged dir proves the net set.

$ f=$(mktemp -d) && mkdir -p "$f/src/groups" && printf '[hostname_groups]\n"h" = [\n  "alpha",\n  "%s/src/local.toml",\n]\n' "$f" > "$f/src/config.toml" && printf '[arch]\npackages = [\n  "keep-pkg",\n  "drop-pkg",  # trailing comments are house style (the valkey line)\n  "lua5.1-style",\n]\n' > "$f/src/groups/alpha.toml" && printf '[arch]\npackages = [\n  "drop-pkg",\n  "local-keep",\n]\n' > "$f/src/local.toml" && .local/bin/tools/metapac-filtered-config --config-dir "$f/src" "$f/out" drop-pkg lua5.1-style nosuch-pkg | sort
filtered: drop-pkg (2 declaration line(s))
filtered: lua5.1-style (1 declaration line(s))
filtered: nosuch-pkg (declared nowhere — nothing to drop)
$ .local/bin/tools/metapac-declared --config-dir "$f/out" --hostname h
keep-pkg
local-keep
$

--- metapac-filtered-config: a relative DEST still writes absolute group paths ---

metapac resolves relative paths in config.toml against its groups dir, so the
re-pointed machine-local path must come out absolute no matter how DEST was
spelled (found live: a relative DEST made metapac error on groups/<dest>/...).

$ mkdir -p "$f/rel" && (cd "$f/rel" && "$OLDPWD/.local/bin/tools/metapac-filtered-config" --config-dir "$f/src" out drop-pkg >/dev/null) && grep -o '"/[^"]*abs-group[^"]*"' "$f/rel/out/config.toml" | sed "s|$f|F|"
"F/rel/out/abs-group-1-local.toml"
