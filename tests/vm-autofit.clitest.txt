# vm-autofit (Story 5.4, #151) — the resolution-hint reactor's testable seams.
# Stubbed xrandr + xinput on PATH record calls; no X server involved. The
# xrandr stub answers -q and --prop from the fixture at $XRANDR_OUT, so a
# test swaps topologies by copying a fixture there. The xinput stub lists a
# tablet only when XINPUT_TABLET is set, so calibration stays deterministic
# on any machine the suite runs on. HOME points at a stub polybar launcher
# that only logs, so bar relaunches are observable; the pgrep stub reports
# running bars only when POLYBAR_UP is set.

$ d=$(mktemp -d) && printf '#!/bin/sh\necho "xrandr $*" >> "$XLOG"\ncase "$1" in -q|--prop) cat "$XRANDR_OUT" ;; esac\n' > "$d/xrandr" && chmod +x "$d/xrandr"
$ printf '#!/bin/sh\necho "xinput $*" >> "$XLOG"\ncase "$1" in\n  list) [ -n "${XINPUT_TABLET-}" ] && echo "$XINPUT_TABLET" ;;\n  list-props) [ -n "${XINPUT_TABLET-}" ] && echo "  Evdev Axis Calibration (270): 0, 1279, 0, 799" ;;\nesac\nexit 0\n' > "$d/xinput" && chmod +x "$d/xinput" && export XLOG="$d/calls.log" XRANDR_OUT="$d/out" PATH="$d:$PATH"
$ mkdir -p "$d/home/.config/polybar" && printf '#!/bin/sh\necho launch.sh >> "$XLOG"\n' > "$d/home/.config/polybar/launch.sh" && chmod +x "$d/home/.config/polybar/launch.sh" && export HOME="$d/home"
$ printf '#!/bin/sh\n[ -n "${POLYBAR_UP-}" ]\n' > "$d/pgrep" && chmod +x "$d/pgrep"
$

$ printf 'Screen 0: minimum 320 x 200, current 1280 x 800, maximum 8192 x 8192\nVirtual-1 connected 1280x800+0+0 (normal) 0mm x 0mm\nVGA-1 disconnected (normal)\n' > "$d/plain" && cp "$d/plain" "$XRANDR_OUT"

vmwgfx fixtures as Xorg's modesetting driver prints them under `xrandr
--prop`: every connector carries the immutable 'suggested X'/'suggested Y'
range properties, and the host's topology sets them. vout NAME STATUS X Y ID
prints one output block:

$ vout() { printf '%s %s (normal left inverted right x axis y axis) 0mm x 0mm\n\thotplug_mode_update: 1 \n\t\trange: (0, 1)\n\tsuggested X: %s \n\t\trange: (0, -1)\n\tsuggested Y: %s \n\t\trange: (0, -1)\n\tCONNECTOR_ID: %s \n\t\tsupported: %s\n\tnon-desktop: 0 \n\t\trange: (0, 1)\n' "$1" "$2" "$3" "$4" "$5" "$5"; }
$ { echo 'Screen 0: minimum 1 x 1, current 1920 x 1200, maximum 16384 x 16384'; vout Virtual-1 'connected 1920x1200+0+0' 0 0 38; echo '   1920x1200     60.00*+'; vout Virtual-2 disconnected 0 0 39; } > "$d/vmw1"
$ { echo 'Screen 0: minimum 1 x 1, current 3024 x 1964, maximum 16384 x 16384'; vout Virtual-1 'connected 3024x1964+0+0' 0 0 38; echo '   3024x1964     60.00*+'; vout Virtual-2 connected 3024 0 39; echo '   3840x2160     60.00 +'; vout Virtual-3 disconnected 0 0 40; } > "$d/vmw2"

apply with an explicit output targets it; with no tablet listed, calibration
stops after the device scan:

$ : > "$XLOG"; .local/bin/tools/vm-autofit apply Virtual-1; cat "$XLOG"
xrandr --output Virtual-1 --auto
xinput list --name-only
$

apply without an output enumerates connected outputs and re-modes each
per-output (bare --auto would skip already-enabled ones); disconnected
outputs are left alone, and with no offset properties there is no --pos:

$ : > "$XLOG"; .local/bin/tools/vm-autofit apply; cat "$XLOG"
xrandr --prop
xrandr --output Virtual-1 --auto

$

react relaunches running bars whenever the topology (outputs and positions)
differs from the last apply — including the first, in case the bars came up
on a stale layout — and a repeat of the same layout leaves them alone:

$ cp "$d/vmw1" "$XRANDR_OUT"; : > "$XLOG"; { sleep 1; cp "$d/vmw2" "$XRANDR_OUT"; printf 'e1\n'; sleep 1; printf 'e2\n'; sleep 1; cp "$d/undock" "$XRANDR_OUT"; printf 'e3\n'; } | POLYBAR_UP=1 .local/bin/tools/vm-autofit react; grep -e ' --output ' -e '^launch' "$XLOG"
xrandr --output Virtual-1 --auto --pos 0x0
launch.sh
xrandr --output Virtual-1 --auto --pos 0x0 --output Virtual-2 --auto --pos 3024x0
launch.sh
xrandr --output Virtual-1 --auto --pos 0x0 --output Virtual-2 --auto --pos 3024x0
xrandr --output Virtual-1 --auto --pos 0x0 --output Virtual-2 --off
launch.sh
$

with no bars running (login, before i3's exec_always starts them) nothing is

$ cp "$d/vmw1" "$XRANDR_OUT"; : > "$XLOG"; { sleep 1; cp "$d/vmw2" "$XRANDR_OUT"; printf 'e1\n'; } | .local/bin/tools/vm-autofit react; grep -c '^launch' "$XLOG"
0

with a SPICE tablet present (and evdev exposing the calibration property),
apply recalibrates the axes to the current size and forces an input-map
rebuild with a no-op transform:

$ : > "$XLOG"; XINPUT_TABLET='spice vdagent tablet' .local/bin/tools/vm-autofit apply Virtual-1; cat "$XLOG"
xrandr --output Virtual-1 --auto
xinput list --name-only
xrandr -q
xinput list-props spice vdagent tablet
xinput set-prop spice vdagent tablet Evdev Axis Calibration 0 1279 0 799
xinput set-prop spice vdagent tablet Evdev Axis Inversion 0 0
xrandr -q
xrandr --output Virtual-1 --transform 1,0,0,0,1,0,0,0,1
$

react applies once up front (a hint may already be pending); a burst of
events coalesces into a single trailing-edge apply, so the final size wins:

$ : > "$XLOG"; printf 'e1\ne2\ne3\n' | .local/bin/tools/vm-autofit react Virtual-1; grep -c -- '--auto' "$XLOG"
2
$

events separated by more than the coalesce window each get their own apply:

$ : > "$XLOG"; { printf 'e1\n'; sleep 1; printf 'e2\n'; } | .local/bin/tools/vm-autofit react Virtual-1; grep -c -- '--auto' "$XLOG"
3
$

react on immediate EOF still catches the pending hint:

$ : > "$XLOG"; printf '' | .local/bin/tools/vm-autofit react Virtual-1; grep -c -- '--auto' "$XLOG"
1
$

rc=2
$ .local/bin/tools/vm-autofit 2>&1; echo "rc=$?"
